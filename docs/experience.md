# NoName 的日常体验

NoName 应该随着工作持续发挥作用，而需要人管理的内容保持少量。一个有用的账本，会让下一次工作从更高的起点开始，也允许你改变主意。

## 从初心到日常动作

[首次提交 `6a07c77`](https://github.com/yuchenlogin/NoNameAgentHarness/commit/6a07c77) 的愿景提出“上下文是资产”，架构把它落在“决策 + 理由 + 指针”上：记忆负责充分，档案负责准确。规范与品味逐渐内化，作品保持焦点，管理动作按需出现。

| 初心 | 今天的使用方式 |
|---|---|
| 上下文可积累、可移植 | 以项目账本为来源，按任务组装上下文包；保留来源，避免依赖某个聊天窗口 |
| 规范逐渐内化 | agent 从重要决定提出候选，人确认后成为项目约束 |
| 例子与判断比形容词更有用 | 保存“认可什么、否决什么、为什么”，明确品味来源 |
| 界面是一张地图 | 先看当前决定与工作接续，再追溯来源、历史与技术信息 |
| 历史可追溯，判断可改变 | 同一主题的新版本经确认后替换当前版本，旧版仍可查 |

这些是设计准则；尚未实现的跨项目同步、任意历史回放等能力不能由愿景推断为已实现。

## 自动、由 agent 选择、由人确认

| 阶段 | Codex | DeepSeek Harness |
|---|---|---|
| 自动留证 | 已启用项目信任 hooks 后记录输入与最终答复 | `autoIngest` 记录宿主工具结果，跳过 NoName 自身读取和投影回声 |
| 接续 | SessionStart 提供有预算的上下文；可用 recall 主动重读 | agent 调用 `noname_package`，不保证宿主自动调用 |
| 选择重要内容 | skills 和启动提示引导少量阶段策展；remember 产生候选 | 工具描述引导 record → remember；extract 默认预览 |
| 确认长期影响 | 人通过账本或明确授权的 review 操作签署 | 人通过同一张账本签署状态；品味审核也需明确决定 |

自动化在“留证”和“准备接续”上减少重复劳动；选择与确认防止记忆无限堆积。没有默认后台 LLM 自动抽取服务，也没有将每轮对话自动批准为长期记忆的机制。

## 一条记忆的合格标准

值得保留的内容，应能回答“下次工作为什么需要它”。优先级通常是：明确决定与约束、对旧决定的修正、关键成果与阻塞、可执行的下一步。写作时保留一句清晰判断、一条理由和真实来源，避免整段聊天粘贴。

例如：

> 决定：首版使用 SQLite。
>
> 理由：只在本地运行，先减少部署成本。
>
> 下一步：实现 add/list，验证关闭程序后数据仍在。

“工具调用成功”“继续加油”和缺少来源的模型猜测通常不值得成为长期状态。是否提出候选仍由 agent 依当前工作判断；相同内容应复用已有记录，差异应解释清楚。

## 改变主意的正确路径

1. 查当前主题的逻辑键与层级，例如 `high / storage`。
2. 提出新决定及变化理由，复用原有键。
3. 确认前保留旧当前版本；确认后新版本生效。
4. 从版本演进回看旧决定和这次修正。

同一键的当前状态只展示有效版本；历史证据仍可包含过去的说法。旧待审候选不会自动判为拒绝。品味修正也通过现有版本生命周期进行，不能把“用户否决一次方案”自动推断为永久审美。

## 2026-10-15 角色走查

这轮使用隔离账本与真实命令进行角色走查；模拟签署仅用于临时测试数据，未批准项目真实待审记忆。它是工程体验验证，不代表已完成外部用户研究。

| 角色与路径 | 实际发现 | 处理 |
|---|---|---|
| 首次接触的开发者：README → 安装 → 空库 → 首条记忆 → 新上下文 | 原 quickstart 是初始化加运行测试，用户看不到“成功记住”的闭环；源码插件 README 声称 prepare 自动构建，但 package 没有 prepare | README 改为按宿主选择入口，展示提出→确认→接续；DSH 显式构建 |
| 长任务中的 Codex 用户：反复保存 → 决定修正 | 相同 remember 产生重复待审；同键确认修正的内核行为正确 | bridge 增加重复候选复用及 unchanged 结果，预览确认后的变化；skills 明确同主题复用键 |
| DSH 用户：空工作区 → package / extract → 账本 | fresh-start 在未初始化时失败；读取结果回流证据会放大回声，还可能保存完整审核 URL | 修复读取入口初始化；跳过自身读取和投影回声；extract 默认预览，记忆写入独立为 remember |
| 阅读和审核者：结构化内容 → 判断 | 结构与 ID 抢占内容焦点，难以区分当前决定、历史与候选 | 默认显示此刻，决定、理由和工作接续前置；来源与 JSON 按需展开 |

首次使用路径实际验证了未启用状态、初始化后的空库、提出候选、模拟确认、同键修正后确认、recall、离线导出与完整性校验。最终当前记忆仅包含新版，历史仍可追溯。隔离配置下的 Codex 安装、重复安装、源码目录外调用与卸载也通过；实际宿主 hooks 是否受信任并运行，仍须在对应聊天用回执验证。

实现与测试结果以当前仓库代码和测试日志为准；技术边界见 [Codex 部署](codex-deployment.md)、[账本指南](ledger.md) 及 [插件 README](https://github.com/yuchenlogin/noname-dsh-plugin#readme)。

最终的测试、CLI 对抗审查、分发验证与发布边界见 [验收记录](ux-validation.md)。
