# 使用交互式账本

账本让你看见三件事：**现在记住了什么、什么需要你判断、这些内容从哪里来。** 日常先读人能理解的决定、理由和进度；事件 ID、JSON 与审计细节按需展开。

这个设计来自 [最初愿景](vision.md)：记忆保留决策与理由，档案保存细节；界面是一张地图，让正在创造的作品成为焦点。

## 打开账本

| 使用入口 | 操作 |
|---|---|
| Codex | 调用 `$noname-ledger`，或运行 `~/.codex/bin/noname-codex ledger` |
| DeepSeek Harness | 让 agent 调用 `noname_ledger` |
| 本地 CLI | 从仓库根运行下面的命令 |

```sh
.venv/bin/python -m noname_harness ledger-serve --db .noname/harness.db --background
```

打开输出中的 `url`。服务默认一小时无活动后退出，链接失效时重新运行命令取得新入口。
省略 `--background` 则在前台运行，用 Ctrl-C 停止。

只需归档浏览时使用离线 HTML：

```sh
.venv/bin/python -m noname_harness ledger-html --db .noname/harness.db --out .noname/ledger.html
# Codex 已部署项目也可以：
~/.codex/bin/noname-codex ledger --static
```

离线快照支持页面内浏览与展开，不写回数据库。要签署候选，请使用本地服务 URL。

想体验完整内容，可从仓库根运行 `.venv/bin/python -m examples.ledger_demo`。它创建临时演示项目，返回空账本、带内容的快照和本地交互入口；演示签署不会作用于自己的项目。

## 从“此刻”开始

| 页面 | 应该在这里获得的答案 |
|---|---|
| 此刻 | 项目当前采用哪些决定？接下来从哪里继续？ |
| 等你判断 | 为什么提出这条候选？确认后会新增还是替换什么？ |
| 品味与偏好 | 这是我明确表达的判断，还是模型观察后提出的候选？ |
| 来路与变化 | 旧结论为什么改变？当前版本依赖哪些来源？ |
| 活动档案 | 某次输入、工具结果、上下文组装或审核的原始记录是什么？ |

卡片优先展示内容、理由与下一步，来源和结构化原文留在详情中。没有已批准记忆时，页面明确保持空状态；活动数量不能替代“已记住”的数量。

活动提示只说明账本中确实存在的事件或上下文组装记录。它不能证明某个宿主的全部 hooks 都正常，更不能证明模型已经遵循了记忆。Codex 的本聊天接入情况请用 `$noname-status` 查看对应 session 的回执。

本地页面每 15 秒只读检查账本变化。“此刻”闲置时自动更新；搜索、展开来源或填写审核时只提示新变化，不打断阅读或丢弃草稿。轮询不会创建记忆，也不会单独延长服务的空闲期限。离线快照保留导出时的内容。

## 确认一条有价值的记忆

1. 打开“等你判断”，读候选的内容、理由、范围及其来源。
2. 如果它修正已有决定，先比较当前版本与候选版本。
3. 填写签署人和理由，逐条选择接受、拒绝、暂缓，或修改后接受。
4. 成功后页面刷新：确认过的内容进入当前状态，来源和审核决定留在历史。

**候选尚未成为事实。** 普通对话被记录并不会自动进入项目规则。优先确认会影响未来工作的决定、约束、明确修正和阶段进度；一次猜测、临时尝试和一般成功日志留在档案即可。

品味单独处理：自述品味必须来自用户明确表达；从模型表现中推断的品味需明确采纳。品味只影响表达、排序和选择，不是技术结论的证据。

| 候选类型 | 页面操作与结果 |
|---|---|
| 项目决定 / 工作进度 | 接受、拒绝、暂缓、修改后接受；暂缓仍在待审列表 |
| 品味候选 | 采纳，或拒绝并退休；没有暂缓操作 |
| 品味卡 | 接受、拒绝并退休、修改候选；修改后仍需另行接受 |

页面不提供批量批准。另一页面或 CLI 已修改同一候选时，旧页面提交会返回冲突；刷新后重新查看最新内容。签署人用于本机审计，不是账号登录。

草稿在当前浏览器会话内保存。恢复时若候选或当前版本已经改变，需先核对，再明确选择继续使用草稿或丢弃草稿；仅改理由不会消除版本警告。同一主题存在多个候选时，页面提示并提供对照，不会暗中批准或拒绝其中任何一条。

## 修正：更新当前版本，保留来路

例如，最初确认了“使用 SQLite，因为首版只在本地运行”，后来决定“改用 PostgreSQL，因为要支持多人协作”。

对同一主题复用同一个逻辑键（如 `storage`），提出新内容和理由。确认前旧版继续有效；确认后当前状态切到新版，版本演进保留旧决定、来源与修正理由。不要为了更新而另造 `storage-v2`、`storage-new` 等键，否则它们会被看成不同主题。

旧话仍可能出现在活动档案和上下文中的历史证据部分，这是来源记录；当前有效的决定以已批准状态为准。账本不删除或偷偷改写曾经发生的事。

## 远程宿主与访问边界

服务仅监听 `127.0.0.1`。完整 URL 包含随机访问令牌，应作为本机访问凭据保管；审核请求校验令牌、Host 和同源 Origin。不要把链接贴到公开 issue。

远程 DSH 的 `127.0.0.1` 指向远程机器。需要把返回 URL 的端口转发到本机相同端口，例如返回端口为 `45678`：

```sh
ssh -L 45678:127.0.0.1:45678 your-host
```

然后在本机浏览器打开原始完整 URL，并保留 `127.0.0.1`、端口和令牌路径。若该本机端口已占用，可在远程重新启动服务取得另一端口。插件不会自动把审核服务发布到公网。

## 数据、投影与现有边界

账本界面从事件、已批准状态、品味、待审项及版本链生成。显示方式可重建；审核仍调用现有内核接口并追加审计记录，页面不自行决定事实。Codex 与 DSH 共用渲染与审核协议。

当前支持按视图浏览、查看来源、版本变化与本地逐条审核。时间缩放、任意节点回放、并排比较上下文包、远程多人账号和跨项目同步仍未提供。技术实现与长期数据契约见 [记忆模型](memory-model.md) 和 [体验模型](experience.md)。
