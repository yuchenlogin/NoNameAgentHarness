# 交互式账本

> 账本不是日志查看器。它把「发生过什么、为什么发生、现在的状态从哪里来」压缩成一个可下钻的交互地图。

## 1. 数据关系

- **Session Log** 是原始事件流；
- **Evidence Store** 保存大内容、文件 diff 与原始响应；
- **Ledger Projection** 从日志派生面向人的关键节点；
- **Memory/Taste** 通过引用连接回账本和证据。

账本自身不创造事实。它随时可以从事件流重建。

## 2. 三种核心视图

### 2.1 Timeline：发生了什么

默认只显示高信号节点：

- 用户目标变化；
- 路由与模型配方选择；
- 高风险审批；
- 关键工具与文件变更；
- 任务完成、失败、回退；
- 记忆/法典/品味的候选和审核。

模型 token chunk、低层重试等默认折叠，需要时展开。

### 2.2 Causal Map：为什么这样做

点击一个结果，可以看到它依赖的：

- 用户指令；
- 法典条目；
- 选中的证据；
- 品味卡（仅标注「影响了排序/表达」，不能显示成事实依据）；
- 模型配方和路由理由；
- 工具结果与审批。

这张图允许用户识别「错误来自证据、记忆、路由、模型，还是工具」。

### 2.3 State Diff：现在为何如此

用 diff 展示：

- 法典 v12 相比 v11 新增/失效了什么；
- 品味卡本月与上月有什么变化；
- 当前任务态由哪些 session event 推导；
- 哪条旧记忆被新证据取代。

## 3. 最小交互

- 时间缩放：会话 → 周 → 项目 → 跨项目；
- 类型过滤：决策、工具、文件、记忆、品味、成本、错误；
- 展开证据：从一句摘要下钻到原始消息或 diff；
- 反向追踪：从一个记忆找到全部支持/反驳证据；
- 回放：从任一稳定节点重建上下文包；
- 比较：并排比较两次模型配方或两个上下文包；
- 纠正：对错误记忆发起失效或替代，而不是直接删除历史。

## 4. 视觉原则

- 默认是一条干净时间线，不默认展示复杂图；
- 因果图只在用户追问「为什么」时展开；
- 颜色表达事件类型，不表达价值高低；
- 一个节点只显示一条主信息，其余是渐进披露；
- 审核操作和普通浏览视觉上明确区分；
- 不用巨量统计面板制造「可观测性很强」的错觉。

## 5. 新颖性落点

账本最重要的新颖点不是画图，而是连接三个过去分离的平面：

1. **运行事实**：工具、文件、模型调用；
2. **认知状态**：法典、任务态、记忆；
3. **个人演进**：品味卡的形成、冲突与退休。

当用户点击一张品味卡，能看到它来自哪些时刻；当用户点击一次代码决策，能看到哪些品味只影响了表达、哪些证据真正支持了技术结论。这种边界清晰的可解释性，才是长期信任的基础。

## 6. 审核收件箱

账本首页只保留一个高价值待办入口：

> `3 条法典候选 · 2 张品味卡待复核`

审核卡显示来源、影响范围、冲突、接受后的变化。批量处理只允许低风险且同质的候选；法典和跨项目品味默认逐条确认。

这类审核请求可以通过系统原生通知呈现：通知只负责把注意力带到一件需要判断的事上，具体证据、冲突和操作仍在账本中完成。低层现场事件不逐条打扰用户；只有可能改变长期状态、存在冲突或模型明确不确定时，才产生注意力请求。

## 7. 原型落地状态

账本 UI 已落地：`noname_harness/ledger_view.py` 从 append-only 事件、审核收件箱与品味投影组装视图模型，生成单文件、无依赖、离线 HTML（`ledger-html` 命令，双击即可在浏览器打开）。

已实现的视图与原则：

- **三种核心视图 Timeline / State / 审核收件箱 + Causal Map 第四视图**：时间线默认高信号节点，低层簿记以 `<details>` 折叠组嵌入、可展开（渐进披露而非删除）；状态视图展示法典/任务态/品味并带来源事件数与审批人；审核收件箱聚合待审候选，以暖色左边框与普通浏览视觉区分。
- **Causal Map 已落地**：`noname_harness/causal_map.py` 从 append-only 事件与 provenance 派生「结果→依赖」投影，`<details>` 渐进披露，嵌入账本 HTML 为第四视图。三类结果节点：法典 revision（依赖 source_event_ids 的用户指令/证据 + 审核提案批准人）、上下文包（依赖选中的证据/记忆 + 模型配方 + 目标模型）、受审批工具执行（依赖审批令牌 + 工具结果）。品味引用的「model moment」事件标为「影响了排序/表达」软影响而非事实依据（从「选中的证据/记忆」中减去）；审批令牌对照账本中的 `tool.approval_granted` 核实，未匹配标「未在账本中核实」；canon 依赖按 id 单独解析，不受 display window 限制。
- **State Diff 已落地**：`noname_harness/state_diff.py` 从 supersedes 链派生版本演进投影——`state_history` 沿 `supersedes_id` 从真 head 回溯（不信时间序，时钟回拨不反转链条）；从所有有历史的 key（含 retired）开始，标注新增/被取代/失效/内容同时变更；每版带 approved_by/created_at + 双时序；`<details>` 渐进披露，嵌入账本为第五视图（审核收件箱/状态/版本演进/因果图/时间线）。
- **纯投影、可重建**：视图模型与因果模型都永不写入，随时可从事件流重建；账本自身不创造事实。
- **视觉原则已遵守**：干净时间线、类型用色不表价值、无巨量统计面板、克制暗色设计（与 site 一致）。

尚未实现：时间缩放与回放/比较等高级交互——属下一步。
